# Ulsan_AR

울산 이벤트용 모바일 웹 AR 체험. 앱 설치 없이 브라우저에서 바로 실행되며, 퍼즐(오브젝트 근접
감지)과 고래구조(손 인식) 두 가지 미니게임을 제공한다.

## 화면 구성

- **`index.html`** — 첫 화면. 배경 이미지(로고/제목/설명 포함) + "모험 시작하기" 버튼 → `camera-intro.html`로 이동.
- **`camera-intro.html`** — 카메라 안내 화면. 카메라 권한/사용법을 안내하고 "카메라 켜기" 버튼으로
  실제 AR 체험(`ar-scene/index.html`)에 진입한다. 뒤로가기 버튼은 첫 화면(`index.html`)으로 이동.
- **`ar-scene/`** — 실제 AR 체험. 퍼즐(`index.html`)과 고래구조(`trash.html`)가 별도 페이지로
  분리되어 있다. 상단 모드 버튼을 누르면 두 페이지 사이를 이동한다.
  - **퍼즐**: 실측 위치(월드 트래킹)로 퍼즐 조각 오브젝트 4개(조각 이미지가 입혀진 평면)가 사용자
    주변에 배치된다. 실제로 걸어서 일정 거리 안까지 다가가면서 그 오브젝트 쪽을 바라보고 있으면
    그 즉시 화면 중앙 2x2 그리드의 해당 조각이 채워지고 오브젝트는 사라진다. 4개를 다 모으면 완성
    이미지가 화면에 표시된다.
  - **고래구조**: 실측 위치(월드 트래킹)로 얼음 오브젝트 5개(`Ice.glb`, 그 안에 숨겨진
    `Jangsaengi.glb` 마스코트)가 사용자 주변에 고르게 흩어져 배치된다. 걸어서 일정 거리 안까지
    다가가 잠깐 바라보면 그 얼음이 제자리에서 "타겟팅"되어(파티클 이펙트가 뜨고 살짝 커짐)
    잡을 대상이 되고, 손을 화면 중앙(잡기 존)에 잠깐 유지하면 "잡기"로 인정된다. 잡은 채로
    손을 흔들면(짧은 시간 안에 방향이 여러 번 바뀌는 움직임) 얼음이 깨지는 이펙트(파편 비산 +
    장생이 등장 후 떠오르며 사라지는 연출)와 함께 사라지며 진행 상황(N/3)이 올라간다. 3개를
    깨면 완료되고, 남은 얼음(최대 2개)은 자동으로 사라진다. 정확한 수치는 아래
    [게임 메커니즘 상세](#게임-메커니즘-상세) 참고.
- **`assets/images/`** — 배경, 로고, 퍼즐 조각 이미지(p_1~p_4), 퍼즐 완성 이미지.
- **`assets/models/`** — 고래구조 모드에서 쓰는 3D 모델. `Ice.glb`(얼음), `Jangsaengi.glb`(장생이
  마스코트).

## 게임 메커니즘 상세

두 모드 모두 8th Wall World Tracking(SLAM)으로 얻는 **실측 카메라 위치/방향**을 기준으로 동작한다.
오브젝트는 카메라가 씬을 시작한 원점 기준 구형 좌표로 사용자 주변에 흩뿌려지고, 이후 사용자가 실제로
걸어서 다가가야만(가만히 서서 화면만 돌려서는 거리가 안 줄어듦) 상호작용이 열린다.

### 퍼즐 모드 (`ar-scene/puzzle.js`)

| 항목 | 값 | 의미 |
|---|---|---|
| 조각 개수 | 4개 | 다 모으면 완성 이미지 표시 |
| 배치 반경 | 1.5m ~ 4.5m | 시작 위치 기준, 랜덤 |
| 배치 높이 | 눈높이 ±0.3m | 카메라 y 기준 |
| 수집 거리 | **3.0m 이내** | 이 거리 밖이면 아무리 쳐다봐도 수집 안 됨 |
| 응시 각도 | **내적(dot) ≥ 0.85** (정면 기준 좌우 약 32도 이내) | 화면 정면 쪽으로 조각이 보여야 함 |

거리·각도 두 조건을 **동시에** 만족하는 순간 대기시간 없이 즉시 수집된다(잡기/흔들기 같은 별도 동작
불필요).

### 고래구조 모드 (`ar-scene/trash.js`)

| 항목 | 값 | 의미 |
|---|---|---|
| 스폰 개수 | **5개** | 사용자 주변에 실제로 배치되는 얼음 수 |
| 완료 목표 | 3개 | 이만큼 깨면 완료 — 나머지 못 깬 얼음(최대 2개)은 그 순간 자동으로 사라짐 |
| 스폰 시점 | **씬 로드 즉시** | 과거엔 SLAM 스케일 추정이 안정될 때까지 3초 스캔 대기를 뒀었는데, 사용자 요청으로 제거하고 트래킹 시작 즉시 배치하도록 변경. 대신 초반 몇 초는 스케일 재추정으로 거리감이 살짝 흔들릴 수 있음(아래 참고) |
| 배치 기준점 | **스폰하는 바로 그 순간의 실제 카메라 위치** | 매번 그 자리 기준으로 360도 배치되므로, 사용자가 서 있는 곳 주변 전방위에 흩어짐 |
| 배치 각도 | 방위각을 5구간으로 나눠 구간별 랜덤 | 순수 랜덤이면 여러 개가 한쪽에 몰릴 수 있어, 360도를 스폰 개수만큼 구간으로 나눈 뒤 그 안에서만 무작위로 배치해 고르게 흩어지게 함 |
| 배치 반경 | 1.2m ~ 3.0m | 스폰 위치 기준, 랜덤. 퍼즐보다 좁게 잡은 건 거리가 멀수록 SLAM 스케일 오차가 커져서 "가까이 가도 거리가 안 줄어드는" 오브젝트가 생기는 걸 막기 위함 |
| 배치 높이 | 눈높이 + 0.9m 부근 | 카메라 y 기준, 세로 범위는 좁게 |
| **타겟팅 거리** | **2.0m 이내** | 이 거리 안에 들어와야 타겟 후보가 됨 |
| **타겟팅 응시 각도** | **내적(dot) ≥ 0.85** (정면 기준 좌우 약 32도 이내) | 거리 조건과 **동시에** 만족해야 타겟 후보가 됨 — 순수 거리만 보면 스케일 오차로 절대 안 가까워지는 경우가 있어 "바라보는지"도 같이 봐서 느슨하게 잡음 |
| **타겟팅 유지 시간** | **1000ms** | 위 거리+응시 조건을 끊김 없이 이 시간 동안 계속 만족해야 실제로 타겟팅됨 — 스쳐 지나가듯 잠깐 조건을 만족한 것만으로 타겟팅되는 것 방지. 도중에 다른 얼음을 보거나 조건을 벗어나면 타이머가 리셋됨 |
| 타겟팅 표시 | 제자리에서 파티클 이펙트 + 스케일 ×1.12 | 얼음이 화면 정면으로 옮겨지지 않고 스폰된 실제 위치에 그대로 있는 대신, 타겟팅되면 그 자리에서 발광 파티클(도는 점 4개 + 은은한 halo)이 뜨고 살짝 커져서 "지금 이게 타겟"임을 표시 |
| **잡기(grab) 판정 존** | 화면 가로/세로 각 35%~65% (중앙 30% 정사각형) | 손바닥 중심(MediaPipe 랜드마크 9번)이 이 영역 안에 있어야 함 — 얼음이 실제로 그 방향에 보이도록 카메라를 든 채 손을 뻗어야 함 |
| 잡았을 때 스케일 | ×1.3 | 타겟팅 스케일(×1.12)보다 한 단계 더 커져서 "쥐었다"는 느낌을 줌. 놓으면 다시 ×1.12(타겟팅 상태)로 돌아감 |
| **잡기 유지 시간** | **400ms** | 손이 잡기 존 안에 이 시간 이상 머물러야 "잡기"로 인정(실수로 스치는 것 방지) |
| **흔들기 판정 구간** | 최근 900ms | 이 시간 동안의 손 움직임을 봄 |
| 흔들기 방향 전환 | 2회 이상 | 좌우/상하로 방향이 뒤집힌 횟수(reversals)가 이 이상이어야 함 |
| 흔들기 최소 이동량 | 0.02 (화면 비율 기준) | 이보다 작은 떨림은 무시 |
| 흔들기 허용 범위 | 0.5 (화면 비율 기준) | 움직임 전체 폭이 이보다 크면(팔을 너무 크게 휘두르면) 흔들기로 인정 안 함 — 손 흔들기 특성상 진폭이 좀 커도 되게 넉넉히 잡음 |
| 파괴 후 쿨다운 | 1000ms | 연속 흔들기 오판정 방지 |
| **파괴 이펙트 시간** | 800ms | 파편 비산 + 장생이 등장/이탈 애니메이션 재생 시간 |
| 얼음 모델 크기 | 0.45m (가장 긴 변 기준) | `Ice.glb`, 로드된 실제 바운딩 박스 기준 자동 스케일 |
| 장생이 모델 크기 | 0.2m (가장 긴 변 기준) | `Jangsaengi.glb`, 얼음이 깨지기 전까지는 숨겨져 있다가(투명 처리가 아니라 `visible:false`) 깨지는 순간 나타나 위로 떠오르며 사라짐 |

**정리하면:** 얼음까지 2m 이내로 걸어가서 그 얼음을 정면(좌우 약 32도 이내)으로 1초 정도 계속
바라보면 타겟팅된다(위치는 안 바뀌고 제자리에서 파티클+확대로 표시). 타겟팅된 뒤에는 그 얼음이
보이는 방향으로 카메라를 든 채 화면 중앙 손바닥 존에 손을 0.4초 이상 대고 있으면 잡히고, 잡은
채로 약 1초 이내에 손을 여러 번 흔들면 깨진다.

**참고: 스캔 대기 제거의 트레이드오프.** 퍼즐 모드(`puzzle.js`)는 여전히 트래킹 시작 후 3초
스캔 대기(`SCALE_SETTLE_MS`) 뒤에 오브젝트를 배치하지만, 고래구조 모드는 사용자 요청으로 이
대기를 없애고 트래킹 시작 즉시 배치한다. 단안 카메라 기반 SLAM은 시작 직후 몇 초간 실측
스케일(m 단위) 추정이 흔들릴 수 있어서, 초반에는 "다가가는데도 거리가 잘 안 줄어드는" 것처럼
느껴질 수 있다 — 몇 초 지나 스케일이 안정되면 정상적으로 동작한다.

### 디버그 모드

`trash.html?debug=1`로 접속하면 화면 우상단에 손 인식 파이프라인 상태(등록/프레임 전달/검출
결과, lock/grab 상태 등)를 실시간 로그로 보여주는 오버레이가 뜬다. 안드로이드 크롬 등에서 손
인식이 안 될 때 원인 파악용.

## 기술 스택

- 빌드 도구 없는 순수 HTML/JS 정적 사이트.
- **AR 엔진**: [8th Wall](https://8thwall.org/) 오픈소스 엔진(`@8thwall/engine-binary`, jsdelivr CDN).
  2026-02-28부로 유료 클라우드 플랫폼(Studio/계정 시스템)은 폐기됐지만, 엔진 자체는 API 키/계정 없이
  무료로 계속 배포된다("제한된 사용 라이선스" — 저작권 고지 유지, 리버스엔지니어링/수정 금지 조건).
  월드 트래킹/SLAM(퍼즐, 고래구조)에 사용.
- **손 인식**: [MediaPipe Hands](https://developers.google.com/mediapipe) (Google, 무료). 별도
  카메라 스트림을 열지 않고, `XR8.CameraPixelArray`로 8th Wall이 이미 받아오는 카메라 프레임을
  그대로 넘겨받아 쓴다(월드 트래킹과 손 인식이 카메라 하나를 공유).
- 배포: GitHub Pages (정적 파일이라 별도 서버 불필요, HTTPS는 카메라 권한을 위해 필수)

## 로컬 실행

```
npm install
npm run dev
```

카메라 기능은 HTTPS가 아니면 브라우저가 권한을 안 준다. PC에서 띄운 걸 폰으로 테스트하려면
`npx localtunnel --port 8080` 같은 터널링 도구로 HTTPS 주소를 만들어 접속하면 된다.
